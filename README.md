# 삼척 키움지도 — 서버 접근 시험과 청소년수련관 수집 시범

이 도구는 GitHub Actions 서버에서 10개 기관의 목록과 **설정된 샘플 상세 페이지**를 읽을 수 있는지 확인합니다. 청소년수련관에는 별도의 수집기를 추가해 목록 첫 페이지의 공고를 `data/programs.json`에 저장합니다. 모든 기관의 프로그램을 빠짐없이 수집하거나, 검수 없이 키움지도에 게시하는 서비스가 완성된 것은 아닙니다.

이 수정본의 시험은 네트워크를 사용하지 않는 회귀시험과 별도의 소규모 실제 접속 확인으로 나눠 진행했습니다. **수정된 수집기의 GitHub Actions 실행 결과는 아직 없습니다.** 저장소에 반영하고 실행한 뒤 서버에서의 접근성과 수집 결과를 확인하세요.

## 현재 시험 범위

| 항목 | 설정 상태 | 해석할 때 주의할 점 |
|---|---|---|
| 대상 기관 | 10개 | 일부 주소는 실제 게시판 목록이 아니라 기관 메인 페이지입니다. |
| 샘플 상세 주소 | 8개 | 일부는 추정 주소이며, 미검증 샘플은 확인필요로 표시합니다. |
| 상세 주소 없는 기관 | 2개 | 목록만 시험하며 상세 접근 가능 여부는 알 수 없습니다. |
| 첨부파일 주소 | 2개 | 청소년수련관과 교육지원청의 설정된 샘플만 시험합니다. |

접근 시험은 공고가 새로 생겼는지와 **제목이 바뀌었는지**만 비교합니다. 처음 정상적으로 읽은 목록은 비교 기준으로 저장하며 기존 글을 신규 공고라고 표시하지 않습니다. 제목이 같은 공고의 본문·접수기간·장소·첨부 변경은 이 비교표에 표시하지 않습니다. 청소년수련관 수집기는 조회한 상세를 다시 파싱하지만, 여러 페이지 순회·본문 이미지 OCR·첨부 내용 추출은 아직 수행하지 않습니다.

## 먼저 내 PC에서 실행하기

Python 3.11을 사용합니다. **파이썬 표준 라이브러리만 사용하므로 pip 설치는 필요하지 않습니다.** ZIP을 압축 해제하고 `README.md`가 있는 폴더에서 실행하세요.

```bash
python -m unittest discover -s tests -v
python scripts/check_access.py
python scripts/collect_youth_center.py
```

실행 후 `results/latest.md`를 열어 결과를 확인합니다. 이 결과는 **내 PC의 접속 결과**이며 GitHub 서버의 결과와 다를 수 있습니다.

## GitHub 서버에서 시험하기

1. 기존 [samcheok-access-check 저장소](https://github.com/numanjoa0422-eng/samcheok-access-check)의 **Code → Add file → Upload files**에서 압축을 푼 파일을 덮어씁니다. **ZIP 파일 자체를 올리는 것으로는 실행되지 않습니다.**
2. 저장소 최상위에 `README.md`, `config/`, `scripts/`, `tests/`, `.github/`가 있어야 합니다. 이 파일들을 `samcheok-access-check/` 같은 상위 폴더 안에 한 번 더 넣지 마세요. 숨김 폴더인 `.github/`도 빠뜨리지 않아야 합니다.
3. `.github/workflows/daily-check.yml`도 함께 교체합니다. 업로드에서 이 폴더가 빠졌다면 저장소의 **Add file → Create new file**에서 정확한 경로로 생성하거나 기존 파일을 편집해 내용을 붙여넣습니다. 기본 브랜치에 반영한 뒤 [워크플로 화면](https://github.com/numanjoa0422-eng/samcheok-access-check/actions/workflows/daily-check.yml)의 **Run workflow**를 눌러 첫 실행을 확인합니다.
4. 실행 화면의 **Summary**에서 기관별 접근 결과와 청소년수련관 수집 상태를 읽고 **Artifacts**에서 결과 파일을 내려받습니다. 저장소 커밋이 성공하면 `results/`, `state/`, `data/`에서도 볼 수 있습니다.

워크플로는 회귀시험, 접근 시험, 청소년수련관 수집 순으로 실행합니다. 수집 단계가 실패해도 요약·artifact·보존된 데이터의 커밋을 먼저 시도하고 마지막 단계에서 실행을 실패로 표시합니다. 커밋이 실패해도 artifact의 결과를 확인할 수 있습니다. 동시에 실행되는 작업은 순서대로 처리합니다.

워크플로 파일에 `contents: write` 권한이 선언되어 있습니다. 결과와 state 커밋이 계속 실패하면 다음 실행에서 비교 기준을 이어받지 못하므로 이 문제를 해결한 뒤 신규·제목 변경 추이를 판단하세요. 저장소 전체 설정을 무조건 쓰기 권한으로 바꿀 필요는 없습니다. 조직 정책이나 보호 브랜치 때문에 커밋이 거부될 수 있으니, 이때는 Actions의 결과 파일을 먼저 확인하세요.

예약 시각은 한국시간 **매일 08:50·13:30**입니다. 워크플로의 UTC 설정은 각각 `23:50`·`04:30`으로 변환되어 있습니다. 예약 실행은 지연되거나 생략될 수 있어 정확한 시각의 실행을 보장하지 않습니다. 처음에는 수동 실행으로 정상 작동부터 확인하세요. 일주일 시험 후 계속 실행할 필요가 없으면 Actions에서 이 워크플로를 비활성화하세요.

## 결과 읽는 법

| 표시 | 의미 |
|---|---|
| 성공 | 해당 단계에서 정상 구조나 기대 내용을 확인했습니다. 전체 기관 수집이 가능한 것으로 확정한 뜻은 아닙니다. |
| 확인필요 | 공고 링크를 못 찾았거나, 기대 내용과 다르거나, 샘플 주소가 미검증인 등 추가 확인이 필요합니다. |
| 실패 | 네트워크·HTTP 오류·빈 응답 등 해당 요청이 실패했습니다. 원인과 재현 여부를 함께 봐야 합니다. |
| 미시험 | 샘플 상세 주소나 첨부 주소가 없어 그 단계를 실행하지 않았습니다. |
| 확인필요 + robots 보류/제한 설명 | robots.txt가 수집을 허용하지 않거나 규칙을 확인하지 못해 해당 요청을 건너뛰었습니다. |

**HTTP 200이나 Actions의 초록색 체크만으로 수집 성공을 판단하지 마세요.** Actions가 정상 종료해도 개별 기관 결과는 실패·확인필요일 수 있습니다. 목록과 상세는 각각 확인해야 합니다.

목록은 인식 가능한 공고 링크가 있어야 성공으로 봅니다. 공고 0건이나 파싱 오류가 발생하면 기존 비교 기준을 지우지 않습니다. 상세는 페이지에 보이는 본문 텍스트와 기대 문구로 확인하며, 추정 샘플의 판정은 제한됩니다. 첨부 주소를 나중에 넣으면 빈 응답·응답 유형·파일 서명을 확인하지만, PDF/HWP 내용 추출이나 이미지 OCR까지 수행하는 것은 아닙니다.

## 청소년수련관 수집 자료를 읽는 법

`data/programs.json`은 공고별 제목·원문 URL·라벨이 있는 대상/일시/장소/신청기간·첨부 URL을 저장합니다. 공지사항에는 휴관 안내와 행사 후기 같은 글도 섞여 있으므로, 저장된 공고 수를 검수 완료된 프로그램 수로 읽으면 안 됩니다. 불확실한 날짜·필드는 비워두고 검토가 필요한 상태를 함께 기록합니다.

목록 수집 실패, 공고 0건, 상세 일부 실패나 구조 변경 시 이전의 공고를 ID별로 보존합니다. 첫 페이지 밖으로 밀려난 글도 자동 삭제하지 않습니다. 따라서 보존된 글의 취소·수정 여부가 계속 검증되는 것은 아닙니다. `last_attempt_at`은 최근 실행 시각이고 `last_success_at`은 최근 수집 성공 시각입니다. 기존 자료의 보존을 새 원문 확인 성공으로 표시하지 않습니다.

신청기간이 분명히 해석되는 공고에만 한국시간 기준 접수예정/모집중/마감을 계산합니다. 연도를 확정할 수 없거나 충돌하는 기간, 종료일만 있는 문구, 시간 단위 마감처럼 해석을 확정하지 못한 조건은 검토가 필요합니다. 선착순 접수·조기 마감·취소 여부는 날짜만으로 판단하지 못합니다. 보존된 기록도 마지막 원문 확인 시각과 검토 상태를 함께 확인하세요. 이미지에만 적힌 정보는 아직 자동으로 읽지 않습니다. 첨부 링크 추출과 첨부 내용 검증도 서로 다른 단계입니다.

## 키움지도 카드 연결

현재 저장소 주소는 `https://github.com/numanjoa0422-eng/samcheok-access-check`입니다. 이 주소를 다시 물을 필요는 없습니다. 수정본을 실행하고 커밋이 성공하면 데이터의 공개 주소는 다음과 같습니다.

```text
https://raw.githubusercontent.com/numanjoa0422-eng/samcheok-access-check/main/data/programs.json
```

키움지도 HTML과 데이터가 같은 웹사이트에서 서비스된다면 `fetch('./data/programs.json', {cache: 'no-store'})`처럼 상대 주소를 사용하세요. 별도 서버에 올린 HTML이라면 실제 데이터 주소를 연결하고 브라우저에서 응답과 CORS를 확인해야 합니다. 컴퓨터에서 HTML 파일을 직접 여는 것만으로는 이 연결을 검증할 수 없습니다.

화면은 이 JSON의 `programs`를 기존 카드 구조에 맞게 변환해야 합니다. 새 게시물은 검수 이후 게시하고, 실패 시에는 마지막 정상 자료와 원문 확인 시각을 표시하세요. 외부 제목·본문은 `textContent`로 출력하고 URL은 HTTP/HTTPS 여부를 확인하세요. JSON을 가져오는 코드만 추가했다고 카드 반영·검수·필터·자료 보존까지 구현된 것은 아닙니다.

## 이 결과로 알 수 없는 것

- 한 번 성공한 사이트가 계속 열리는지, 모든 공고·팝업·첨부를 빠짐없이 읽을 수 있는지.
- 공고 내용이나 날짜가 정확한지, 실제 신청 가능한지, 원문에 없는 내용을 추정할 수 있는지.
- robots.txt 외의 이용약관·자료 이용 조건·기관의 별도 수집 정책이 운영을 허용하는지.

이 도구는 목적을 밝히는 User-Agent를 사용하고 robots.txt를 확인합니다. 확인할 수 없거나 금지된 요청은 보류하며 차단 우회를 시도하지 않습니다. 보류·실패 결과만으로 기관이 모든 자동화를 금지했다고 단정할 수는 없습니다. 필요하면 기관에 공식 데이터 제공이나 허용된 수집 방식이 있는지 문의하세요.

## 파일 구성과 설정 변경

| 파일·폴더 | 역할 |
|---|---|
| `config/targets.json` | 기관 주소, 공고 링크 패턴, 샘플 검증 조건 |
| `scripts/check_access.py` | 접근 시험과 결과 생성 |
| `scripts/collect_youth_center.py` | 청소년수련관 첫 페이지 공고 수집 시범 |
| `data/programs.json` | 수집 자료와 검토 상태; 실행 시 생성 |
| `tests/` | 네트워크에 의존하지 않는 단위시험 |
| `.github/workflows/daily-check.yml` | 수동·예약 실행 설정 |
| `state/` | 정상적으로 확인한 공고의 비교 기준 |
| `results/history.jsonl` | 기관별 원시 결과 누적 |
| `results/latest.md` | 최신 결과 요약 |
| `results/latest.json` | 최신 결과 원시 데이터 |
| `requirements.txt` | 추가 설치가 필요 없음을 설명하는 파일 |

기관을 추가하거나 주소를 고칠 때는 **실제로 확인한 목록·상세·첨부 주소**를 사용하세요. 샘플의 기대 문구도 그 페이지와 맞아야 합니다. 추정 주소는 미검증 표시를 유지하고, 설정 후 단위시험과 수동 실행으로 확인하세요. 접근 시험이 통과한 채널부터 별도의 실제 수집기를 만들고 게시 전 검수를 연결하는 것이 다음 단계입니다.
