# 삼척 키움지도 자동수집 수정본

기존 GitHub 저장소: https://github.com/numanjoa0422-eng/samcheok-access-check

이 묶음은 기존 청소년수련관 수집에 **추가 게시판 7곳**을 연결하는 수정본입니다. 저장소 반영과 GitHub Actions 첫 실행은 아직입니다. 웹사이트를 공개하는 설정은 포함하지 않았습니다.

이 업로드용 ZIP에는 비공개 미리보기 HTML이 없습니다. 압축을 푼 안쪽 파일·폴더 전체를 업로드하면 됩니다. 이전 ZIP을 이미 올렸다면 저장소에 남은 `kiwoom-preview.html`은 별도로 삭제해야 합니다. 새 ZIP 업로드만으로 기존 파일이 삭제되지는 않습니다.

## 한 번만 할 일

1. ZIP을 압축 해제합니다. ZIP 파일 자체가 아니라 **안에 있는 파일·폴더**를 저장소 최상위에 올려 기존 같은 경로의 파일을 바꿉니다. `.github/workflows/daily-check.yml`도 포함되어야 합니다. 새 상위 폴더 안에 통째로 넣으면 워크플로가 실행되지 않습니다.
2. 저장소 **Actions → 삼척 키움지도 - 접근·추출 시험 → Run workflow**를 한 번 실행합니다.
3. Summary의 **추가 기관 자동수집** 표와 커밋 결과를 확인합니다. 녹색 실행 표시만으로 모든 기관·필드 수집이 성공했다는 뜻은 아닙니다.

워크플로에 `permissions: contents: write`가 있으므로 저장소 전체 기본 권한을 먼저 바꿀 필요는 없습니다. 커밋 권한 오류가 실제로 발생하면 해당 실행 로그와 저장소·조직 정책을 확인합니다.

이후 기존 예약인 매일 **08:50·13:30 한국 시간**에 실행됩니다. GitHub 일정 실행은 지연될 수 있습니다. 이 단계에서는 공고마다 승인을 누르지 않습니다. 제보 승인은 별도입니다.

## 확인할 화면

미리보기 HTML은 업로드 ZIP에 포함하지 않습니다. 대화에서 별도로 받은 최신 미리보기 파일을 내려받아 브라우저에서 열면 됩니다. 이 파일은 개인 확인용이며 웹사이트 공개가 아닙니다. 기존 제목·날짜 목록, 오늘의 업데이트, 클릭 상세, 기간 선 달력을 유지했습니다.

화면은 기존 `data/programs.json`과 새 `data/board-programs.json`을 독립적으로 읽습니다. 처음 열 때와 5분마다 저장자료를 확인하며 GitHub 원본 캐시 때문에 바로 보이지 않을 수 있습니다. 연결 실패·잘못된 JSON은 마지막 정상 자료를 유지하고 화면에 사유를 표시합니다. 추가 기관 자료도 파일에 초기 스냅샷을 담았지만 최신 성공 결과라고 보장하지 않습니다.

삼척시청·EDUPIA 직접 자동수집은 여전히 보류 상태입니다. 시청 robots 확인 실패와 EDUPIA 경로 제한을 우회하지 않습니다. 보건소·체력인증센터·청년센터·강원대·기사의 모든 새 정보를 이 수집기가 자동 확보하는 것은 아닙니다. 별도로 설정한 검색·미리보기 갱신 작업과 구분합니다.

## 자료와 실패 처리

- 본문에서 명시된 제목·대상·일정·신청기간·장소를 추출하고 원문 주소와 본문 해시를 남깁니다. 정원 잔여석을 확인하지 않았으므로 날짜만으로 모집중을 확정하지 않습니다.
- 이미지와 첨부파일은 원본 링크만 확보합니다. OCR·첨부 내용 추출·첨부 다운로드 완료로 표시하지 않습니다. 본문 범위가 확인되지 않으면 제목·링크만 확보한 부분 수집입니다.
- 날짜·대상 미확인은 **확인 필요**로 표시합니다. 대상 미확인은 전체·일반에만 표시하며 특정 학생 단계의 참가자격을 추정하지 않습니다.
- 접수 종료 모집은 활동일이 남아도 지난공고로 이동합니다. 별도로 확인된 일반 관람·체험 행사는 행사일까지 유지합니다. 접수기간 자체가 미확인이면 임의 마감을 만들지 않습니다.
- 처음 확보한 자료가 이미 마감·종료된 경우 오늘의 새 공고로 올리지 않습니다. 기존 공고의 실제 마감·취소 변경은 업데이트로 알릴 수 있습니다.
- 목록 실패, 일부 상세 실패, 첫 페이지에서 사라짐, 출처 비활성화 시 이전 공고를 삭제하지 않습니다. 유지 자료는 재확인 실패·부재 상태를 기록합니다.
- 같은 원문 주소는 중복을 줄입니다. 과거 확인 자료와 새 본문이 충돌하면 이전 확인을 그대로 새 내용에 적용하지 않습니다.

이번 세션에서 실제 실행한 결과는 **21건 저장, 완료 1곳·부분 2곳·실패 4곳**이었습니다. 실패 사유는 시간 초과였습니다. 이 실행은 GitHub 운영 환경에서의 성공 여부를 대신하지 않습니다. 테스트 데이터의 브라우저 시험도 실제 모든 기관 접속 성공의 증거는 아닙니다.

## 파일 구조와 직접 실행

```text
.github/workflows/daily-check.yml
scripts/check_access.py
scripts/collect_youth_center.py
scripts/collect_boards.py
config/targets.json
config/collection-targets.json
tests/
data/board-programs.json
kiwoom-preview.html
```

이 ZIP에는 **기존 `data/programs.json`을 넣지 않았습니다.** 저장소의 최신 청소년수련관 자료를 덮어쓰지 않기 위해서입니다. 새 `board-programs.json`은 최초 부분 수집 스냅샷이며 이후 Actions 실행 결과로 갱신됩니다.

Python 표준 라이브러리만 사용합니다.

```sh
python -m unittest discover -s tests -q
python scripts/check_access.py
python scripts/collect_youth_center.py
python scripts/collect_boards.py
```

추가 수집기는 전체 약 6분·기관별 약 90초의 요청 예산을 사용합니다. 전체 기관이 실패하면 0이 아닌 종료 코드를 반환합니다. 부분 실패는 결과표로 명시하며 워크플로 전체가 성공이어도 기관별 표를 확인해야 합니다. 커밋 전에 Artifacts에 자료를 보관합니다.

설정에서 출처를 끄거나 제거해도 해당 기관의 이전 자료와 출처 메타데이터는 보존합니다. 현재 활성 기관의 성공·부분·실패 집계에는 비활성 출처를 섞지 않습니다.

## 두 AI가 함께 수정할 때

이 저장소를 수집 코드와 자료의 기준으로 사용합니다. 전체 HTML 사본을 각각 새로 만들지 말고 최신 파일과 변경 범위를 공유합니다. 원문 검토와 구현을 나누고 같은 변경을 다른 AI가 검토합니다. 미리보기의 재빌드 소스·근거·화면 시험은 별도 `kiwoom-source-check.zip`에 보존했습니다. 사용자 제보·삭제 요청을 독립적인 공식 원문 확인으로 바꾸어 쓰지 않습니다.

제보 접수·승인·이미지 저장은 아직 같은 브라우저에서만 시험하는 기능입니다. 공용 접수함과 관리자 인증은 공개 전에 연결해야 합니다.
